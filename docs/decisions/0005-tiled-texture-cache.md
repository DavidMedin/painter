# Cache the canvas as multi-resolution document-space tiles

## Status

Accepted. Amends [ADR 0004](0004-pencil-splat-stroke-rendering.md): strokes are still derived as instanced gaussian splats, but they are no longer replayed every frame. The per-stroke batch cache and paint-order seeds described there are replaced by what follows.

## Context

ADR 0004 drew every stroke every frame with one `drawRawAtlas` call per stroke and rebuilt the active stroke from scratch on each pointer move. Frame cost therefore grew with the total number of splats in the document (about 13 per document unit of stroke), including during pan, zoom, and rotate, and drawing latency grew with the active stroke's length. Measured with a throwaway benchmark (same machine, `flutter test` debug binding, 1920×1080 view, strokes of 40 points): UI-thread display-list recording took 4.3 ms, 22 ms, and 79 ms per frame at 100, 500, and 2000 strokes.

## Decision

- **Tiles.** The visible canvas is composed from square textures (tiles) in a document-space grid. Every tile is 512×512 device pixels; a tile at level of detail (LOD) `L` rasterizes `2^L` pixels per document unit and covers `512 / 2^L` document units per side. Levels run from -4 to 5, which spans the `0.1`–`16` zoom limits at device pixel ratios up to about 4. LOD is `ceil(log2(zoom × devicePixelRatio) - 0.5)`, so a tile is never magnified by more than √2. Tiles are keyed `(x, y, level)`; geometry lives in `lib/canvas/tile_grid.dart` and is pure Dart.
- **Constant tile cost.** Because the texture size is fixed, memory (1 MiB per tile) and raster cost per tile do not depend on zoom. A viewport needs roughly 40 tiles at any zoom, up to about 270 at the lowest zoom with a rotated 1920×1080 viewport.
- **Drawing over tiles.** Strokes are appended in order and pencil ink is black with accumulating alpha, so each tile records how many document strokes it already contains. When a stroke is added, only the strokes a tile has not applied (and that touch it) are drawn over the tile's previous image; earlier strokes are not redrawn. A tile no new stroke touches is left unchanged with no GPU work. Splats that straddle a tile edge are drawn into both tiles (a 2-unit bleed plus the splat extent in `PencilSplats.inkMargin`), so tile seams are invisible.
- **Lazy and asynchronous.** `paint` never builds anything: it draws what is cached and calls `TileCache.request` for what is missing or stale. Requests are queued, limited to 2 tile rasters in flight, and dropped when a later frame no longer wants them (panning away). A finished tile calls `notifyListeners`, which repaints the canvas on its own. Splat generation, the CPU-heavy part, runs in one long-lived worker isolate (`lib/canvas/splat_worker.dart`): stroke points go in as a flat `Float64List` and the result returns as `TransferableTypedData`. Splats are document-space, so each stroke is generated once and reused by every tile and level. Rasterization uses `Picture.toImage`, which completes asynchronously.
- **Stale or wrong-resolution tiles stay visible.** A stale tile is drawn from its old image until its update lands. A tile missing at the target level is drawn from the nearest cached coarser level, cropped and scaled up; if none exists, from cached finer tiles scaled down. One source is used per area, so ink is not doubled. The replacement swaps in when it finishes.
- **Eviction.** Least-recently-used, with a floor of 256 tiles that grows to twice the last frame's working set. Tiles the last frame drew or fell back to, and tiles being built, are never evicted.
- **Active stroke.** The in-progress stroke is not tiled. `SplatStream` (`lib/canvas/pencil_splats.dart`) appends splats for only the new points, so a pointer move costs time proportional to the new points, not the stroke length. `PencilSplats.build` is now `SplatStream` run once, so there is one generation path.
- **Stable seeds.** A stroke's seed is its 1-based index in the document (`CanvasStroke.seed`), assigned at commit or load. The active stroke uses `document.nextSeed`, so its grain is identical before and after pointer-up. This replaces ADR 0004's paint-order seed assignment and its assumption of at most one commit between paints.
- **Document replacement.** Attaching a different `CanvasDocument` discards all tiles and generated splats.
- `PencilRenderer` is removed; `TiledRenderer` (`lib/canvas/tiled_renderer.dart`) owns the sprite, the cache, and the active-stroke stream. `CanvasController.activePoints` now returns the live read-only view instead of a copy, with a new instance per stroke.

## Consequences

- Measured with the same benchmark after the change: steady-state frame recording is 0.03 ms, 0.01 ms, and 0.006 ms at 100, 500, and 2000 strokes (about 12 tiles drawn), a pan frame is at most 0.2 ms, and an active-stroke pointer move is about 0.06–0.08 ms median on a 300-point stroke. Per-frame cost no longer grows with stroke count. These are debug-binding UI-thread recording times, not on-screen frame times or GPU times; raster-thread cost of drawing ~40 tile images was not measured in a running app.
- The work moved to the background: warming every tile of a 2000-stroke document took about 1.5 s in the test binding. Until a tile lands, the user sees a scaled lower-resolution version or, for a region never drawn at any level, blank paper for a moment.
- Memory is about 1 MiB per cached tile (about 40 MiB for a typical viewport, more when rotated or zoomed far out, plus retained off-screen tiles up to the budget). Generated splat buffers are kept per stroke for the session and are not evicted, so memory grows with total splat count (24 bytes per splat). Evicting rarely used strokes' splats is not implemented.
- A tile rebuilt after eviction is rebuilt from all strokes touching it, so panning back to an evicted region costs a full tile build.
- Drawing an incremental stroke over an old tile image re-samples that image once per update. At LOD 0 the draw is 1:1 and the pixel test matches direct drawing; repeated updates at non-integer magnification were not measured for accumulated blur.
- Tiles are anchored to document space, so a stroke far from the origin still maps to ordinary tile indices (negative indices are covered by tests). Documents with very large extents were not tested.
- Seeds are now stable within a document, but still not persisted. Opening a file assigns seeds by stroke order, which equals the order they were drawn, so a document saved and reopened re-derives the same specks. Deleting or reordering strokes, if ever added, would change seeds and needs a persisted seed or id.
- Not verified: behavior in the running macOS window (no windowed run was permitted by [testing.md](../testing.md)), physical stylus latency, the visual quality of the scaled-fallback transition, and GPU time or texture-memory pressure on real hardware.
